# 上海大阪 GitHub Actions 配置与验收

正式条件：2027-02-15 去、2027-02-22 回，上海 SHA（城市全部机场）↔大阪 OSA（城市全部机场），
1 成人经济舱；往返含税票价加去回程托运行李费用合计 ≤ CNY 2800。允许付费加购，未知费用不按零元。

`config.monitor.yaml` 是 Actions 唯一正式配置。原 12 月东京行程不参与定时运行，示例也已改为大阪。
保留 `monitor.yml` 原定时：Asia/Shanghai 的 00:25、08:25、13:25、19:25。
该工作流不生成旧泸州北京配置，也不将报价报告公开推到 Pages。

当前状态：配置、条件判定和验收流程已实现，**不代表正式监控已启用**。
只有仓库变量 `FLIGHT_MONITOR_ENABLED=true` 才启动正式采集；应在云端取价与行李证据均通过后设置。
请勿在尚未补齐下述数据链路时开启。

## 当前缺口

携程 PC 采集器目前只读取去程卡的往返组合起价，没有选定返程航班，也没有两程托运加购费用。
上游被复用的往返解析器同样没有提供这些证据，不能据航空公司名称推测免费托运，不能把无行李报价算成符合预算。
因此新条件默认待核实，低价通知不会谎报达标。

`RoundTripQuote.baggage_offer` 定义了后续适配器所需证据：
已确认去返组合、含税票价，两程均确认存在至少正重量/件数的托运，并明确额外费用（免费时为 0）。
判定将两程额外费用加到票价，仅合计不超阈值时提醒；当前真实采集器尚未填充这些字段。

## 云端验收

`cloud-acceptance.yml` 在专用验收分支 push 时查询一次同一行程：无账号、无本机登录态、无通知密钥、无重试。
结果附件 `osaka-cloud-acceptance` 中为 `data/cloud-acceptance.json`。
`status=ok` 表示取得基础组合价；`baggage_verified=false` 仍表示未达到完整需求，进程以 2 退出。
被拦截、需登录、解析失败也明确报告，不当成无票，不自动重试。

本机 Edge 会话不会自动复制到 GitHub。跨操作系统/出口地址的会话可用性未经验证；
本方案没有读取或上传 Cookie，也没有上传整个浏览器档案。
如果匿名云端查询被拦，应先记录结果并暂停，不反复请求或自动切换账号/出口。
