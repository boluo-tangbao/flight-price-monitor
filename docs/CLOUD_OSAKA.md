## 当前缺口

正式配置启用 `crawler.round_trip_fare_details`。携程先打开往返列表，从其中已加载的候选选最低起价的去程，
再展开最多三个最低起价的返程及每组最多两个报价，按各自的「行李规定」读取两程托运额度。
当两程都有明确包含的正额度时，使用该方案的含税往返价作为含托运总价。
详情未展示加购价时标为待核实，不把无免费托运误记为免费，也不会触发达标提醒。

`RoundTripQuote.baggage_offer` 定义了后续适配器所需证据：
已确认去返组合、含税票价，两程均确认存在至少正重量/件数的托运，并明确额外费用（免费时为 0）。
判定将已核实的两程额外费用加到票价。低于或等于预算时沿用低价提醒。
本轮没有确认达标的方案时，发送一条已查方案摘要，最多三条，排序优先比较已核实的含托运总价，
不足三条时补充托运待确认的票价或起价。详情读不到时仍保留已查到的价格，且只展示实际取得的条数。
名单限于本轮展开的候选，不能代表整个平台的最低三项。如果连列表也无法读取，则记录采集状态，
沿用原健康告警。整个读取流程停在行李规则，未进入下单。

## 云端验收

`cloud-acceptance.yml` 在专用验收分支 push 时查询一次同一行程：无账号、无本机登录态、无通知密钥、无重试。
结果附件 `osaka-cloud-acceptance` 中为 `data/cloud-acceptance.json`。
`status=ok` 表示取得基础组合价；`baggage_verified=false` 仍表示未达到完整需求，进程以 2 退出。
被拦截、需登录、解析失败也明确报告，不当成无票，不自动重试。

本机 Edge 会话不会自动复制到 GitHub。跨操作系统/出口地址的会话可用性未经验证；
本方案没有读取或上传 Cookie，也没有上传整个浏览器档案。
如果匿名云端查询被拦，应先记录结果并暂停，不反复请求或自动切换账号/出口。
